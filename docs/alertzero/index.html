03 / BEHAVIOR NOTES

The distinctions that matter

These details explain what the connections mean—and when a downstream worker has work to do.

01

Tuning uses closures, not just verdict tags

An az:false_positive tag alone does not qualify an alert. Rule Tuning checks that its status is closed and its closing reason is false_positive. Analysts can supply these closures too, so Tuning does not exclusively depend on Alert Triage.

02

Discovery runs independently of triage

Both workers read security alerts. There is no mandatory Triage → Discovery execution chain. Triage’s closures can change the population eligible for a later discovery sweep.

03

A coverage subject is not a confirmed gap

Hunt writes subjects for completed hunts with confirmed hits and clean hunts. Rule Coverage then assesses the detection rules. An existing enabled rule may already cover the subject.

04

Stored handoffs are picked up on a sweep

Hunt supplies Rule Coverage’s subjects. Attack Discovery’s approved handoff supplies Forensics’ requests. Writing a record does not immediately start the consumer. Existing pending records can still be consumed after their producer is disabled.

05

Hunt can propose responses directly

Continuous Threat Hunt can propose containment based on its own findings. The current worker graph has no Hunt → Forensics handoff; Forensics consumes the requests produced by Attack Discovery’s handoff action.

06

Rule changes feed future detections

Approved tuning and coverage actions change the detection rules that produce future alerts. Explore this feedback loop in the complete data-flow map below. It does not directly trigger another worker.
